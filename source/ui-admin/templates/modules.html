Every capability this deployment carries is a discovered module. This screen shows each one's installed state (whether it is on this image's module path) and its enabled state (whether its enable flag is switched on), with its contributed settings beneath. Where a module declares an enable flag you can switch it here; the change is written through the same store the Settings screen edits, so a live toggle applies on a node's next scheduled re-read and a restart one only on its next boot. Whether a module is installed at all is an image-build decision (the image's feature set), never a runtime one — a module you do not see was not built into this image.

Orphaned-data diagnostic as of - — a deployment-wide store walk refreshed at most once a minute, not re-run on every render, so a just-purged module may still be counted for up to a minute.

Orphaned data

These modules are no longer installed but their declared key-spaces still hold data. Nothing is removed automatically - an incomplete image or a mid-rolling deploy looks the same as an intentional removal. If the removal was intentional, purge it here (the counts are what is deleted), or script it with jenreg purge <module> or POST /api/admin/purge?namespace=<module>.
