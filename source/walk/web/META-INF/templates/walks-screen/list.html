A walk reads every object in the store, and a scheduled walk is a recurring cost: every run pays a read per pointer, per inventory row and per blob it hands its consumers - a round trip each over an object store - and whatever the consumers riding it read and write on top. Nothing here is needed while every node shuts down cleanly: every change is applied on the write path, and a walk exists to repair what a crash left behind. Schedule as many walks as you like, each a cron expression in UTC and the consumers that ride it, and read what the last run of each one measured before you shorten a cadence.
